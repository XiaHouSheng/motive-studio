# Motive Studio 动效规划方案

## 1. 设计目标

Motive Studio 是一个面向 AI 解题与结构化思考的工作台，动效服务于信息组织、交互反馈和 AI 任务状态，而不是装饰。

### 核心原则

1. **克制**：避免大面积弹跳、持续闪烁和无意义的循环动画。
2. **有因果**：只有在状态发生变化时才触发动效。
3. **有空间连续性**：面板展开、题目切换、步骤定位尽可能让用户感知到前后关系。
4. **状态可感知**：用户能够分辨等待、生成、完成、失败和取消。
5. **不阻塞操作**：动画进行期间，用户仍然可以滚动、输入和执行其他操作。
6. **性能优先**：优先使用 `transform` 和 `opacity`，避免频繁触发布局计算。
7. **尊重系统偏好**：支持 `prefers-reduced-motion`，减少动态效果。

---

## 2. 动效分级

所有动效分为三个级别。

| 级别 | 用途 | 时长参考 | 设计要求 |
|---|---|---:|---|
| L1 微交互 | Hover、按下、选中、图标反馈 | 100–160ms | 快速、轻量 |
| L2 结构变化 | 面板展开、弹窗、列表插入、步骤切换 | 180–280ms | 清晰、连续 |
| L3 重点状态 | AI 生成、任务完成、跨区域定位 | 300–500ms | 有表达力但不拖沓 |

以上时长是初始设计值，后续应结合真实界面测试调整。

**禁止默认使用 L3 动效处理每一次普通操作。**

## 3. 全局动效规范

### 3.1 时间曲线

建议定义统一的 CSS 动效变量：

```css
:root {
  --motion-fast: 120ms;
  --motion-normal: 200ms;
  --motion-slow: 320ms;

  --ease-standard: cubic-bezier(0.2, 0, 0, 1);
  --ease-enter: cubic-bezier(0, 0, 0.2, 1);
  --ease-exit: cubic-bezier(0.4, 0, 1, 1);
  --ease-emphasized: cubic-bezier(0.2, 0, 0, 1);
}
```

### 3.2 动画属性优先级

优先使用：

- `transform`
- `opacity`
- `background-color`
- `border-color`
- `box-shadow`（谨慎使用）

尽量避免对大面积内容持续动画化，尤其是包含大量题目、公式和代码的区域。

### 3.3 统一的减少动效模式

```css
@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
```

减少动效模式下，不能删除必要的状态反馈；应保留颜色、图标、文字等非运动提示。

## 4. 工作台三栏动效

### 4.1 左侧：题目与分组导航

左侧承担分组、题目和步骤的定位功能，动效需要强化层级关系。

#### 分组展开

- 展开时，子列表淡入并轻微向下展开。
- 收起时，子列表快速淡出。
- 时长建议：180–220ms。
- 不要让每一行依次大幅飞入。

#### 当前题目切换

- 当前项背景与文字状态平滑过渡。
- 左侧强调线或选中标记使用短距离位移。
- 时长建议：140–180ms。
- 不要整份导航树重新播放入场动画。

#### 新增题目

- 新题目插入列表后轻微淡入。
- 新增成功后，短暂强调该条目。
- 用户主动添加的题目可以自动定位；后台同步新增则不应抢夺焦点。

#### 拖动排序

- 被拖动项跟随指针。
- 目标位置实时预留空间。
- 放置成功后平滑归位。
- 拖动失败时恢复原位置，并提供明确反馈。

### 4.2 中间：结构化解题区域

这是工作台最重要的阅读区域，应该以稳定、易读为主。

#### 题目切换

- 新题目内容淡入。
- 如果切换前后题目属于同一分组，可采用轻微横向位移。
- 如果切换到完全不同的工作区，优先淡入，不必强行模拟空间移动。
- 时长建议：180–240ms。

避免整个页面明显左右飞动，尤其是在用户连续查看多个题目时。

#### 步骤新增

- 新步骤在目标位置淡入。
- 高度变化平滑完成。
- 新增后可轻微强调步骤标题或边框。
- 不要让所有后续步骤依次闪烁。

#### 步骤展开与折叠

- 展开内容时，使用高度与透明度变化。
- 收起时优先保证阅读位置稳定。
- 若步骤包含复杂公式、图片或代码，应避免在动画过程中重复执行昂贵的渲染操作。

#### 步骤更新

AI 修改某个步骤时：

1. 保留原有步骤位置。
2. 只对发生变化的内容做轻量强调。
3. 可短暂改变边框或背景。
4. 高亮结束后恢复正常状态。

不要在每次 AI 更新时把整个答案重新播放入场动画。

### 4.3 右侧：讨论与 AI 对话

讨论区需要表达消息流动和 AI 生成状态，但不能干扰阅读。

#### 用户发送消息

- 新消息快速淡入。
- 不需要明显弹跳。
- 如果消息发送成功与服务端确认是两个独立状态，应分别显示，避免提前宣告成功。

#### AI 回复

- 回复容器出现时轻微淡入。
- 流式文本优先自然显示，不对每个字符额外添加动画。
- Markdown、代码块和公式逐步生成时，应尽量避免反复改变整个消息的布局。

#### 新消息到达

- 如果用户正在底部阅读，保持正常自动跟随策略。
- 如果用户已经滚动到历史消息，不要强制把视口拉回底部。
- 可显示“有新消息”提示，由用户主动跳转。

#### 讨论分支切换

- 新分支淡入。
- 如果切换前后的上下文存在明确的父子关系，可以采用轻微横向位移。
- 不要让每次分支切换都表现成整页路由跳转。

## 5. AI 任务状态动效

AI 任务需要有明确的状态机。动效应根据真实任务状态变化，而不是仅依赖一个持续旋转的图标。

### 状态定义

```text
idle
  └─> preparing
        └─> running
              ├─> streaming
              ├─> completed
              ├─> failed
              └─> cancelled
```

实际实现可以根据接口能力合并部分状态，但前端状态不能与真实任务进度冲突。

### 各状态表现

| 状态 | 视觉反馈 | 注意事项 |
|---|---|---|
| 准备中 | 轻量状态图标或短提示 | 不应无限显示模糊的“思考中” |
| 执行中 | 小型进度指示器 | 不知道百分比时不要伪造进度 |
| 流式输出 | 内容逐步出现 | 不要逐字播放造成阅读延迟 |
| 已完成 | 状态图标或短暂强调 | 不需要庆祝动画 |
| 失败 | 错误提示与重试入口 | 不应只改变颜色 |
| 已取消 | 停止指示器并保留已有结果 | 清楚区分取消与失败 |

### 长任务处理

当任务耗时较长时：

- 显示任务名称和当前可确认的阶段。
- 如果支持取消，应提供明确的取消入口。
- 如果支持后台执行，应允许用户离开当前区域。
- 任务完成后，只有在用户需要关注结果时才显示提示。

不允许使用持续闪烁、快速变色或无限循环的高强度动效制造“AI 很忙”的假象。

## 6. 重点体验：讨论内容回流到解题步骤

这是 Motive Studio 有别于普通聊天工具的核心体验，应单独设计。

当用户在右侧讨论中深入询问某个步骤，并最终将解释整理回正式解题内容时，建议采用以下反馈：

1. 用户触发“整理到解题步骤”。
2. 目标步骤出现短暂的定位强调。
3. 目标步骤内容更新。
4. 新增或修改的内容短暂高亮。
5. 右侧讨论消息保留，并显示已整理或待确认的状态。

### 视觉要求

- 目标步骤的定位强调应短暂、清晰。
- 更新内容的高亮应在数秒内自然消退。
- 不应把整份答案重新渲染成一段长动画。
- 如果 AI 只是提出修改建议，还没有正式应用，必须使用“待确认”状态，不得提前表现为已更新。

### 交互原则

动效只负责帮助用户发现变化，不能代替版本记录、撤销和确认机制。

对于覆盖旧内容的操作，优先提供撤销或版本恢复能力。

## 7. 弹窗、菜单与浮层

### 普通弹窗

- 背景遮罩淡入。
- 弹窗轻微缩放并淡入。
- 关闭时快速淡出。
- 不使用夸张的弹簧动画。

建议时长：180–220ms。

### 菜单与 Popover

- 轻微位移加透明度变化。
- 菜单项不必逐个延迟入场。
- 快捷菜单应尽可能迅速出现，不能让动效拖慢高频操作。

### Toast

- 从边缘轻微进入并淡入。
- 自动消失时淡出。
- 成功、警告和错误状态应同时提供文本或图标，不能只依赖颜色。

## 8. 移动端动效

移动端主要承担题目拍摄、上传、整理和快速查看，因此动效应更加直接。

### 拍照与上传

- 选择图片后立即显示本地预览。
- 上传过程中显示真实进度；无法获取进度时显示不确定进度指示器。
- 上传成功后平滑切换到已完成状态。
- 失败时保留图片与重试入口，避免用户重新选择。

### 添加题目

- 添加题目后提供轻量成功反馈。
- 如果需要用户继续填写题目内容，焦点应自然进入下一步。
- 不要在每次添加题目后播放较长的全屏动画。

### 页面切换

- 优先使用短距离滑动或淡入。
- 手势导航应优先保证跟手与连续性。
- 不要把桌面端三栏面板动画直接照搬到手机上。

### 扫码加入局域网工作区

- 扫码成功后显示连接状态。
- 连接中与连接失败应有清晰区别。
- 连接成功后再进入工作区。
- 如果连接失败，应保留重新连接和修改地址的入口。

---

## 9. 加载、空状态与错误反馈

### 骨架屏

适用于确实存在异步加载的内容。

- 骨架结构应与真实内容接近。
- 只在必要区域出现。
- 短暂加载可以直接显示轻量指示器，避免闪现骨架屏。

### 空状态

空状态不需要持续运动。

可以使用静态图形、简短说明和明确的下一步操作。

### 错误状态

错误状态以信息传达和恢复操作为主。

- 不使用剧烈抖动作为唯一错误反馈。
- 不让错误提示自动快速消失。
- 如果错误可以恢复，应明确提供重试入口。

## 10. 技术实现建议

### 10.1 先建立统一动效层

将动效参数集中管理，不要在每个组件中随意填写不同的时长和曲线。

建议分为：

- `motion-tokens.css`：时间、曲线与距离变量。
- `transitions.css`：通用淡入、淡出与面板过渡。
- 组件内部状态动画：步骤、消息、上传和 AI 任务等专属交互。

### 10.2 动效工具选择

如果项目使用 Vue：

- 简单状态切换：CSS Transition。
- 列表插入、删除与排序：Vue Transition / TransitionGroup。
- 页面或面板过渡：Vue Transition。
- 复杂时间轴、拖拽或多阶段动画：只有确实需要时才引入专用动画库。

不要为了几个淡入淡出效果额外引入大型依赖。

### 10.3 与业务状态解耦

动画不应该成为业务状态的唯一存储方式。

例如：

```ts
type TaskStatus =
  | "idle"
  | "preparing"
  | "running"
  | "streaming"
  | "completed"
  | "failed"
  | "cancelled";
```

界面根据真实业务状态渲染，动画只负责状态之间的视觉过渡。

对于可被中断的动画，应确保重复触发、快速切换和组件卸载不会留下错误状态。

### 10.4 性能要求

- 避免在大列表中同时播放大量动画。
- 避免对高频更新的流式文本应用逐字动画。
- 避免在动画期间反复销毁并重建复杂公式或代码组件。
- 对长列表优先使用局部更新。
- 不要无条件对所有元素添加 `will-change`。
- 移动端优先保证触摸响应与滚动性能。

## 11. 分阶段实施（与当前代码对齐）

### 现状盘点（2026-10-27）

已具备：

- `apps/web/src/styles/globals.css` 已有 `rise-in` / `dot-pulse` 关键帧、`thinking-dot`、`prefers-reduced-motion` 全局兜底。
- 移动端抽屉（`workspace-shell.tsx`）已有 `transition-transform` / `transition-opacity`（200ms）。
- 聊天消息已有 `animate-rise` 入场；流式回复有光标脉冲与「正在生成/停止/中断」状态文案。
- `:focus-visible` 全局焦点样式；按钮与图标均为 `transition-colors`。
- 弹窗（`components/ui/dialog.tsx`）目前直接挂载/卸载，无入场与退场动画。

### P0：基础一致性

- [x] 建立全局动效变量：`--duration-fast/normal/slow`、`--ease-standard/enter/exit`，动画统一走 `animate-*` 工具（内部引用时长与曲线变量），组件时长用 `duration-(--duration-fast)` var 引用。
- [x] 统一按钮、徽章的反馈时长（`duration-fast`）。
- [x] 弹窗统一入场（遮罩淡入 + 面板缩放淡入）与快速退场（120ms 淡出）。
- [x] 减少动效支持：补齐 `scroll-behavior: auto`。
- [x] 键盘操作与焦点状态：沿用全局 `:focus-visible`，Radix 菜单自带焦点管理。
- [x] 动效不阻塞操作：全部使用 `transform` / `opacity`，无遮挡交互。

### P1：工作台核心动效

- [x] 当前题目切换：题目标题区淡入（`key={question.id}` + `animate-fade-in`）。
- [x] 新增题组 / 新增题目：输入框区域淡入。
- [x] 消息发送与 AI 流式回复：沿用 `animate-rise`（符合 L2/L3 分级，不做逐字动画）。
- [ ] 分组展开与收起：当前分组为扁平列表、无折叠结构；引入折叠时按 180–220ms 淡入展开子列表，不做逐行飞入。
- [ ] 步骤展开 / 折叠 / 新增：步骤卡片当前无折叠状态；待折叠功能落地后统一高度过渡，避免公式/代码重复渲染。
- [ ] AI 任务状态机：当前用 `Loader2` 旋转 + 文案区分状态，后续收敛为「思考中/生成中/停止中/失败」统一状态组件，长任务可取消。
- [ ] 讨论内容回流：归档应用到正式步骤后，对目标步骤短暂高亮，数秒内消退；提案未应用前保持「待确认」态。

### P2：移动端与高级交互（后续迭代）

- [ ] 图片选择与上传状态：真进度 / 不确定进度指示器；失败保留图片与重试入口。
- [ ] 扫码连接与重连：连接中/成功/失败清晰区分，保留修改地址入口。
- [ ] 拖动排序：拖拽项跟随指针、目标位实时留空、放置归位、失败恢复。
- [ ] 跨区域定位与高亮：归档后定位目标步骤并短暂高亮。
- [ ] 长任务：后台执行、明确取消入口，完成提示仅在用户需要关注结果时出现。

### 落地说明（P0/P1 已实现部分）

- 动效变量集中在 `globals.css` 的 `@theme`，组件内不再散落硬编码时长。
- 全部新动画为 `transform`/`opacity`，走 `--duration-*` / `--ease-*`；`prefers-reduced-motion` 下统一 0.01ms 快进。
- 弹窗退场在共享 `Dialog` 内实现（120ms 淡出后卸载），业务层无感知。
